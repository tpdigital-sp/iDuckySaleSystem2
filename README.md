# 🦆 iDucky Prints Studio

เว็บไซต์ร้านค้าออนไลน์แบบ Print-on-Demand (พิมพ์สินค้าตามสั่ง) — Next.js 15 + React 19 + Tailwind CSS 4

## รันโปรเจกต์

Node.js ติดตั้งไว้ที่ `~/.local/node-v22.23.1-darwin-arm64` (เครื่องนี้ไม่มี node ใน PATH)

```bash
export PATH="$HOME/.local/node-v22.23.1-darwin-arm64/bin:$PATH"
npm install        # ครั้งแรกครั้งเดียว
npm run dev        # เปิด http://localhost:3000 (หรือพอร์ตที่ว่าง)
npm run build      # โปรดักชันบิลด์ (อย่ารันขณะ dev server เปิดอยู่ — จะทับ .next)
```

## สิ่งที่ทำแล้ว (เฟส 1)

- ✅ หน้าแรก — แบนเนอร์โปรโมชัน, จุดเด่นร้าน, หมวดสินค้า 5 หมวด, สินค้าขายดี, สินค้าแนะนำ
- ✅ หน้ารายการสินค้า (`/products`) — กรองตามหมวด (ผ่าน URL param), ค้นหา, เรียงราคา/ยอดนิยม/คะแนน
- ✅ หน้ารายละเอียดสินค้า (`/products/[id]`) — รูปหลายมุม, ตัวเลือกขนาด/สี/วัสดุ (+ราคาเพิ่ม), จำนวน, ราคาอัปเดตเรียลไทม์
- ✅ ตะกร้าสินค้า (`/cart`) — เพิ่ม/ลบ/แก้จำนวน, แยกตามตัวเลือกที่เลือก, ค่าส่ง 2 แบบ, ส่งฟรีเมื่อครบ ฿999 พร้อมแถบความคืบหน้า, บันทึกลง localStorage
- ✅ หน้าวิธีสั่งซื้อ (`/how-to-order`) — 6 ขั้นตอน + FAQ
- ✅ หลังบ้านแบบ UI Demo (`/admin`) — แดชบอร์ดภาพรวม, รายการคำสั่งซื้อ (กรองตามสถานะ, ดูรายละเอียด, เปลี่ยนสถานะ — ยังไม่บันทึกจริง), จัดการสินค้า:
  - แต่ละสินค้ามี **หน้าแก้ไขแยก** ที่ `/admin/products/[id]` — แก้ชื่อ/ราคา/รูป (เพิ่ม-ลบ-แก้)/จุดเด่น/ตัวเลือก+ราคาบวกเพิ่ม/**เนื้อหารายละเอียดสินค้า (body)** ได้ครบ พร้อมแสดง URL สินค้า + ปุ่มคัดลอก + ปุ่ม "เปิดดูหน้าจริง"
  - **การแก้ไขสินค้าบันทึกลง localStorage** (`src/lib/product-store.ts`) — หน้าร้าน (หน้าแรก/รายการ/รายละเอียด) อ่านข้อมูลที่แก้แล้ว จึงกดดูหน้าจริงเห็นผลทันที รีเฟรชไม่หาย (แต่อยู่เฉพาะเบราว์เซอร์เครื่องนั้น) · ปุ่ม "รีเซ็ตทั้งหมด/คืนค่าเริ่มต้น" มีให้
  - ออเดอร์ยังเป็น mock ใน `src/lib/admin-data.ts` และยังไม่มีล็อกอินแอดมิน
- ✅ Responsive มือถือ, ฟอนต์ Prompt (รองรับไทย), PWA manifest เบื้องต้น, ทุกหน้าเป็น static (First Load JS ~106 kB)

## โครงสร้างหลัก

- `src/lib/products.ts` — ข้อมูลสินค้า 18 รายการ 5 หมวด + ราคา/ตัวเลือก/ค่าส่ง (แก้สินค้าที่นี่)
  - รองรับ **กฎเงื่อนไขตัวเลือก** (`rules`): เมื่อเลือก A แล้วจำกัดตัวเลือกของกลุ่ม B เช่น กระดาษ Canvas → เคลือบเหลือแค่ "ไม่เคลือบ" (ดูตัวอย่างที่สินค้า `postcard-print`) — กลุ่มที่เหลือตัวเลือกเดียวจะแสดงเป็นข้อความล็อก 🔒 บนหน้าสินค้า และราคา/ตะกร้าใช้ค่าที่ถูกกฎเสมอ (`resolveSelections`)
- `src/lib/cart-context.tsx` — state ตะกร้า (React Context + localStorage)
- `src/app/(shop)/` — หน้าฝั่งลูกค้า (มี Navbar/Footer/ตะกร้า), `src/app/admin/` — หลังบ้าน (มี sidebar ของตัวเอง)
- `src/lib/admin-data.ts` — ออเดอร์จำลอง + สถานะออเดอร์สำหรับเดโมหลังบ้าน
- `src/components/` — Navbar, Footer, ProductCard, ProductVisual (ภาพ placeholder แบบ gradient+อีโมจิ)

## ต่อ Supabase (ฐานข้อมูลจริง + ล็อกอินแอดมิน)

ระบบรองรับ Supabase แล้ว — ถ้ายังไม่ตั้งค่า จะทำงาน**โหมดเดโม** (localStorage) เหมือนเดิม พอใส่คีย์ครบจะสลับเป็น DB จริงอัตโนมัติ

**ขั้นตอนเปิดใช้:**
1. คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ค่าจริงจาก Supabase (Project Settings → API): `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, และ `SUPABASE_SERVICE_ROLE_KEY` (สำหรับสคริปต์ seed เท่านั้น)
2. เปิด Supabase → SQL Editor → วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ → Run (สร้างตาราง products/profiles + RLS + is_admin)
3. Supabase → Authentication → Users → Add user (อีเมล+รหัสของแอดมิน) แล้วรัน SQL ตั้ง role=admin (คำสั่งอยู่ท้ายไฟล์ schema.sql)
4. `npm run seed` — นำเข้าสินค้าทั้ง 64 รายการเข้า DB
5. รีสตาร์ต `npm run dev` → หลังบ้านจะบังคับล็อกอิน, หน้าร้าน/หลังบ้านอ่าน-เขียนจาก Supabase จริง

**สถาปัตยกรรม:** สินค้าเก็บเป็น JSONB (`products.data` = Product เต็ม) + คอลัมน์ query (id/name/category/price/sold/featured/badge/sort) · RLS: ใครก็อ่านสินค้าได้ เขียนได้เฉพาะ role=admin · Auth ผ่าน Supabase Auth (client-side) · โค้ดเข้าถึงข้อมูลผ่าน `src/lib/product-repo.ts` (สลับ Supabase/เดโมให้เอง)

## รูปสินค้าจริง

หน้าแก้ไขสินค้า (`/admin/products/[id]`) อัปโหลด **รูปถ่ายจริง** ได้แล้ว ทั้งภาพหลัก (โชว์บนการ์ด) และรูปหลายมุม (โชว์บนหน้ารายละเอียด) — ระบบย่อรูปด้วย canvas เป็น JPEG กว้าง/สูงไม่เกิน 700px เก็บเป็น data URL ใน localStorage (เดโม) · `ProductVisual` แสดง `<img src>` ถ้ามีรูปจริง ไม่งั้น fallback เป็นอีโมจิ+สีพื้น · ตอนต่อ cloud storage จริงให้เปลี่ยนที่เก็บจาก data URL เป็น URL ไฟล์บน storage
